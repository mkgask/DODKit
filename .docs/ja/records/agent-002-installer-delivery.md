# Decision Record: agent-002-installer-delivery

## メタデータ
- Status: Accepted
- Date: 2026-04-03
- Scope: インストールおよびブートストラップ導線

## 背景とリサーチ
カスタムエージェントの導入はクリーン環境で簡単に再現できる必要があります。
手作業のコピー手順は反復セットアップでミスと時間ロスを招きます。

リサーチ結果:
- ワークスペースカスタマイズはファイルベースであり、スクリプトで配備可能です。
- Linux/macOS/WSLではシェルインストーラーが最小摩擦の導入方式です。
- 単一エントリのインストーラーで、必要ディレクトリ作成とテンプレート配置を安全に実行できます。

参照:
- https://code.visualstudio.com/docs/copilot/customization/overview
- https://code.visualstudio.com/docs/copilot/customization/custom-agents
- https://code.visualstudio.com/docs/copilot/customization/prompt-files

## 決定
DODエージェント資産を想定パスに配備するためのリポジトリインストーラースクリプトを作成します。

インストーラー責務:
- 実行前提条件の検証
- 必要ディレクトリの作成
- カスタマイズファイルのインストール/更新
- 導入後の確認手順の表示

この親決定の下には、次の現在有効なサブ決定を `DECISIONS.yml` に持ちます。
- テンプレートファイルをインストーラー入力とすること
- 初期CLI対応を GitHub Copilot Chat のみに限定すること

これらのサブ決定の詳細な経緯と理由は、この履歴ファイルに記録します。

## 決定契約
### 不変条件
- インストーラーは冪等であること（複数回実行しても安全）。
- 書き込み先は対象ワークスペースのカスタマイズパスに限定する。
- エラー時は即時失敗し、原因を明示する。
- 生成または配置対象のカスタマイズファイルは、テンプレート資産をソースとする。
- CLIターゲットは明示指定を必須とし、未対応ターゲットは拒否する。

### 非目標
- グローバルなシステムパッケージ導入は行わない。
- ユーザーレベルのVS Code設定を自動変更しない。
- 既存ファイルをサイレントに上書きしない。上書きはユーザーが明示的に許可した場合に限る。
- 初期リリースでの複数CLI同時対応は行わない。

### 受け入れ基準
- 初回実行で必要なDODエージェントファイルをすべて作成できる。
- 再実行時に重複作成や破損が発生しない。
- 出力に成功状態と次の検証アクションが明記される。
- テンプレートと出力先パスが分離され、将来のCLI拡張が可能である。
- `copilot` 指定時に、現在のテンプレート一式を想定ワークスペースパスへ配置できる。
- 対象ファイルが既に存在する場合は、ユーザーが明示的に許可しない限り既存ファイルを維持する。

### 失敗条件
- 再実行で重複設定が発生する。
- 宣言範囲外ファイルを変更する。
- 必要ファイル欠落のまま成功終了する。
- 未対応CLI指定をサイレントで受け入れる。
- 既存対象ファイルをユーザー確認なしで上書きする。

## 議論更新（2026-07-18）
- `curl -fsSL https://raw.githubusercontent.com/mkgask/DODKit/main/install.sh | bash` による再インストールで、変更された `templates/agent.md` は取得されましたが、上書き確認に肯定回答がなく `.github/agents/dod.agent.md` がスキップされました。
- `dod.agent.md` は `PROTECT_FROM_OVERWRITE` には含まれておらず、通常のマニフェスト管理対象です。スキップの原因は、変更された保護対象外アセットをコピーする前に、既存ファイル共通の確認経路へ入ることでした。
- 利用者向けの再インストール目的は、固定された installer を再実行することで宣言済み DOD アセットを更新できることです。`DECISIONS.yml` はプロジェクトデータとして常時保護し、同一内容の管理対象は引き続き `Already up-to-date` とします。
- 候補方針は、再インストール時に変更されたマニフェスト管理対象を既定で更新し、バックアップを作成しないことです。これは宣言済み出力をインストーラー管理ファイルとして扱うことを意味し、そこへのローカルカスタマイズは現在のテンプレートで置き換えられます。

## 議論検証更新（2026-07-18）
- この候補方針は、対話入力や別個の更新コマンドを要求せず、再実行で現在の agent と skill templates を配布できるため、元のインストーラー目的に適合します。
- ワークスペース内限定、テンプレートソース利用、冪等性、早期失敗という既存の拘束条件を維持します。既存の `DECISIONS.yml` 保護は独立した不変条件として残り、上書き挙動より常に優先されます。
- これは宣言済み管理対象に対する従来の上書き確認ルールを変更しますが、変更範囲はマニフェストの配置先に限定されます。未宣言パスやプロジェクトの決定データへの書き込みを許可するものではありません。
- `DECISIONS.yml` の `agent-002-8-existing-file-overwrite-policy` を更新して管理対象再インストールルールを昇格し、その後インストーラーとドキュメントをまとめて検証します。

## 議論更新（2026-07-18）
- 続くフィードバックにより、`--overwrite` を省略した場合は変更済み管理対象ファイルごとに確認し、`a` の入力で現在のインストールを一括上書きへ切り替える案が提示されました。
- 候補プロンプトは `Overwrite this file? [Y/n/a] (a = all):` とします。Enter は現在のファイルだけを許可し、`n` は現在のファイルだけを保持し、`a` は現在のファイルを上書きしたうえで、以降の変更済み管理対象をすべて確認なしで上書きします。上書きが肯定既定であり、ファイルごとの `n` が使えるため、all-no の短縮入力は設けません。
- `a` による切り替えは現在のインストール処理中だけ有効とします。明示された `--overwrite yes|no` は引き続き優先し、非対話時の `ask` は自動更新を継続し、`a` の後も `DECISIONS.yml` は保護します。

## 議論検証更新（2026-07-18）
- 候補方針は、現在の管理対象テンプレートをすべて更新したい一般的なケースで確認の繰り返しを減らしつつ、例外のファイルには個別の `n` を使えるため、元の再インストール目的を維持します。したがって all-no の短縮入力は不要です。
- プロンプトは `Overwrite this file? [Y/n/a] (a = all remaining files):` とし、`a` の範囲を明示します。Enter と `n` は現在のファイルだけに作用し、`a` は現在のファイルに適用したうえで、現在のインストールを `--overwrite yes` と同じ実効挙動へ切り替えます。
- 切り替えは現在のインストール処理だけで有効にします。将来の実行へ影響せず、明示された `--overwrite no` を上書きせず、既存の保護対象チェックを迂回して `DECISIONS.yml` を上書きすることもありません。非対話時の `ask` は回答を取得できないため自動更新を継続します。
- 検証では、`a` を一度入力した後の複数ファイルが追加確認なしで更新される流れを、既存の Enter、`n`、明示的な yes/no、非対話、保護対象、冪等性、シンボリックリンク、各ターゲットのマニフェスト検証と合わせて確認します。
- この挙動を `agent-002-8-existing-file-overwrite-policy` に昇格し、セッション切り替えと正確なプロンプト表示を実装・検証します。
