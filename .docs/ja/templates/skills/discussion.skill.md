# 議論

## 目的
このスキルは Gate A の手順 1、すなわち discussion のために使う。
役割は、現在の決定ランドスケープを意図的に広めだが境界付きで把握し、その後に重要な焦点領域へ絞り込み、その履歴を `records/{discussion-id}.md` に記録することであり、決定昇格より先にそれを行う。

## 必須入力
- 議論 ID
- 対象決定 ID 群または決定スコープ
- 要求スコープ
- 当初の目的または問題定義
- `DECISIONS.yml` 上の対象 status
- 問題の起点になる近傍ファイル、テスト、コマンド、振る舞い、またはドメイン面

## 手順
1. 有効な決定の基準線を確定する。
   現在の対象決定、既存の record link、そしてこの議論が応えるべき当初の目的を確認する。
2. 絞り込み前に、境界付きの広めのスキャンを行う。
   現在の目的と要求スコープを境界として、関連ドメイン、隣接関心事、想定インターフェース、既存拘束条件、明らかな考慮漏れリスクを洗い出す。早すぎるトンネル視野を避けられる程度には広く見るが、無制限の探索にはしない。
3. 深掘り対象の焦点領域を選ぶ。
   広めのスキャン結果から、今回の判断を最も左右しそうなドメイン、ファイル、振る舞い、決定オブジェクトへ絞る。何を焦点にするか、何を当面のスコープ外に置くか、何が未確定かを明示する。
4. 更新前に記録の境界を確認する。
   1つの記録は1つのまとまった意思決定テーマに絞る。独立した質問、コンポーネント、またはフォローアップが現れたら、無関係な履歴を延長せず、新しい `discussion-id` の記録を開始して前の記録を参照する。現在の記録が概ね10エントリまたは1,000語に達したら、自然な区切りで閉じて新しい記録へ続けることを優先する。これはレビュー可能性のためのヒューリスティックであり、強制上限ではない。
5. 議論記録を更新する。
   `records/{discussion-id}.md` がなければ `.dodkit/templates/discussion-record.md` から作成し、既にあれば EOF にだけ追記する。
6. 現時点の状態を簡潔に記録する。
   なぜ今議論するのか、広めのスキャンで得た実質的な発見、選んだ焦点領域、現時点の結論、昇格が保留かどうかを残す。
7. 次の検証対象を明示する。
   その結論を拘束力ある決定にする前に、discussion-validation が何を確認または否定すべきか、特に置き忘れてはいけない隣接論点を含めて明確にする。
8. 議論の境界で止める。
   このスキルでは決定昇格を行わず、候補方向だけを discussion-validation に渡す。

## ガードレール
- 記録更新前に `DECISIONS.yml` を編集しない。
- このスキルで実装を始めない。
- 有効な決定集合は軽量に保ち、履歴はここに残し、拘束条件だけを後で昇格する。
- 実装フェーズのように最初から局所化せず、まず影響ドメインと考慮漏れリスクが見える程度には広く見る。
- ただし広めのスキャンは、当初の目的と要求スコープを境界にした bounded broad scan に留め、無制限のリポジトリ地図作りへ流れない。
- 独立したテーマをまたいで記録を延長したり、レビューしにくくなった後も追記を続けたりせず、自然な区切りで新しい discussion ID を開始する。
- record は追記専用とし、更新前提の追跡フィールドを入れない。

## 完了条件
- `records/{discussion-id}.md` が存在し、最新の議論エントリが入っている。
- 影響ランドスケープが、焦点領域の選択を正当化できる程度には広く確認されている。
- 現時点の結論が検証できる粒度で明示されている。
- 焦点領域、明示的な除外、主要な不確実性が記録上で見える。
- 記録の境界を確認し、分割が必要な場合は新しい discussion ID と前の記録への参照を使っている。
- 次に何を検証するかが明確である。
- 拘束力のあるルールがチャットにだけ残っていない。
